Security, privacy and robustness after a second full review. Nothing to do on your side: update as usual.

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.3.10-x64-setup.msi`**, or let RDM install it by itself (the "Version 0.3.10 available" card) |
| Debian / Ubuntu | `rdm_0.3.10-1_amd64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.3.10-1.x86_64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`: extract, then `sh install.sh` |
| Chrome / Edge / Brave / Opera / Vivaldi… | from RDM (the "Browser extension" card), or `rdm-chromium.zip` |
| Firefox / Waterfox / LibreWolf / Floorp / Zen… | from RDM, or `rdm-firefox.xpi` (extension 0.4.7) |

## Security

- **Cookies and site logins never travel in clear**: a video stream (HLS) or a separate audio track given over HTTPS could send them to an `http://` segment of the same site. Not any more.
- **YouTube module: nothing runs unchecked.** yt-dlp is installed only if its checksum list carries the signature of yt-dlp's own key (written in RDM). Deno, bgutil and the drawing library bgutil needs are exact versions checked against SHA-256 values written in RDM, and no package's install script runs (one used to download its library without any check). A module installed earlier keeps working; installing it again uses the new checks.
- **Updates**: the package is checked again at the very last moment against the fingerprint its signature covers — on Linux by the administrator step itself, from a copy only it can write — so no program can swap it between RDM's checks and the installation.
- **Local bridge**: a web page can no longer tell that RDM is installed.
- **VirusTotal**: the API key never follows a redirect out of VirusTotal.
- **Proxy**: a proxy address RDM cannot use is an error; the quality list, the link check, the file name lookup, VirusTotal and the update check never went through it but around it — no longer.
- **Build**: `web-ext`, which signs the Firefox package, is pinned with its whole dependency tree, and moves to version 10.7 (10 fewer known flaws in its dependencies).

## Privacy

- **Clipboard** (Windows): what a password manager copies — marked private by it — is not even read.
- Cookies are shared between subdomains the way browsers do it in more cases: two people's sites on one hosting platform (`alice.github.io`, `bob.github.io`) are two sites; a broadcaster's own servers (`www.zdf.de`, `cdn.zdf.de`) are one.

## Fixed

- **Linux**: a long Japanese, Chinese, Russian or emoji title failed with "File name too long" (Linux counts bytes, not characters). Names now fit.
- A video stream with huge segments could take gigabytes of memory while waiting for its turn: it is now bounded, and a playlist with more than 200,000 segments is refused.
- A server answering a part of another version of the file (another size) is no longer mixed into the download.
- The YouTube module, when it takes too long, now ends Deno with yt-dlp (it used to keep running, hundreds of megabytes).

## Better

- The window no longer waits for the disk when a download is added (a network drive, a sleeping hard disk).
- Browser recordings: the files stay open between chunks (Windows' antivirus used to scan the whole file again at each one); a recording is capped at 64 GB.
- Long downloads keep a short resume file (finished pieces joined).
- Install scripts: the Windows one only stops RDM's own copies; the Linux one quotes the program's path correctly whatever the home folder's name.

Checked on Windows 11 and on Ubuntu 26.04 (WSL): the full test suite, the YouTube module installed from scratch with every check (a video's links read), the published 0.3.9 packages verified end to end, and the extension's checks.
