A faster, more adaptive download engine: slow connections are replaced, picky servers are handled, and downloads reach full speed sooner.

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.3.5-x64-setup.msi`**, or let RDM install it by itself (the "Version 0.3.5 available" card) |
| Debian / Ubuntu | `rdm_0.3.5-1_amd64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.3.5-1.x86_64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`: extract, then `sh install.sh` |
| Chrome / Brave / Opera / Edge | from RDM (the "Browser extension" card), or `rdm-chromium.zip` |
| Firefox / Waterfox | from RDM, or `rdm-firefox.xpi` (extension 0.4.4) |

## New

- **Slow connections replaced**: a connection far slower than the others from its start (a bad route), or silent while the others receive, is closed and replaced at once, and its piece goes to the others. On a test server where one connection in five crawls, a 96 MB download went from 14 s to 3.3 s.
- **Full speed sooner**: connections double every half second while that pays off (every second before). On servers that cap each connection, a 96 MB download went from 2.2 s to 1.5 s.
- **Servers that cut off programs posing as a browser** (for example Hetzner's mirrors): RDM asks again as a common download tool. These downloads failed before; they now run at full speed.
- **Servers limiting connections or requests** (429/503): RDM obeys `Retry-After`, never asks for more connections than the server accepted, and remembers both for the next downloads from that server. A server counting requests (OVH's mirrors) gets as few as possible: a 100 MB file that took 71 s now takes about 11 s the first time, then well under a second.
- **One round trip less** per download: the first request already brings the first bytes of the file.
- The pieces of a download are split by measured speed, so that they end together; the file is opened once for all connections (fewer system calls, and no antivirus scan at each piece on Windows).
- YouTube module: at most two extractions at once.
- A recording can no longer be made to create files without end.
