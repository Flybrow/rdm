Downloads that adapt to the connection, automatic resume after a cut, and the browser extension installed from RDM.

![RDM](https://raw.githubusercontent.com/vincentxjoubert-lang/rdm/main/docs/screenshots/dashboard-dark.png)

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.2.0-x64.msi`**: double-click, installed for your account, no administrator rights. From RDM 0.1.0: the "Version 0.2.0 available" card installs it in one click |
| Ubuntu 26.04 | from the source code: `sh install-ubuntu.sh` |
| Debian / Ubuntu | `rdm_0.2.0-1_amd64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.2.0-1.x86_64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`: extract, then `sh install.sh --autostart` |
| Chrome / Brave / Opera / Edge | **from RDM** (the "Browser extension" card), or `rdm-chromium.zip`: extract, then "Load unpacked" |
| Firefox | **from RDM**, or `rdm-firefox.xpi` |

## What's new

- **Adaptive connections**: a download starts with 8 connections and doubles every second while all goes well; when connections fail (timeouts, cuts, a server refusing with 429/503), it drops some and the others take over their share. A weak Wi-Fi, a saturated router or a picky server find their pace instead of failing with "timed out".
- **Automatic resume**: RDM rides out up to 3 minutes without data (Wi-Fi dropping, sleep, server gone), then puts the download back in the queue and retries by itself for about half an hour, from where it stopped. The card shows "RETRYING", the reason, the countdown and a *Retry now* button.
- **Extension installed from RDM**: a new "Browser extension" card (the window also opens by itself at first start). RDM detects Firefox, Chrome, Brave, Opera, Edge and Chromium, shows those the extension is connected from, and **Install** prepares the extension, opens the browser on its extensions page and guides the last two clicks. RDM keeps the installed extension up to date.
- **Instant add**: a link sent by the browser appears in the list at once (the real file name is asked from the server in the background).
- Downloads running when RDM closed (or the computer shut down) **resume by themselves** at the next start.
- The extension confirms each hand-off in the page ("✓ Sent to RDM: file.zip") and explains a failure.

## Fixes

- **Extension: some downloads never reached RDM.** The extension asked RDM before pausing the download: a fast file (small file, fibre) had time to finish in the browser, and a busy RDM (more than 0.6 s to answer) let everything through. The pause is now immediate.
- **Cascading "timed out"**: 32 connections opened at once saturated modest connections, and a single failing connection made the whole download fail.
- **Firefox extension not linked to RDM**: the approval question shows as soon as the extension loads (no longer at the first, refused, download), a "!" badge and a message say when to approve, and closing the question no longer counts as a refusal.
- A link sent twice within a few seconds is no longer added twice.
- Pause responds at once while a download is being prepared (server probe, HLS playlists).
- HLS streams: resume point every 20 s (a crash no longer restarts from zero).
- List and settings synced to disk before being replaced: a power cut can no longer leave an empty list.

## Good to know

- **Firefox** only keeps extensions signed by Mozilla. This version's `rdm-firefox.xpi` is not signed: RDM installs it as a temporary add-on (to reload after each Firefox restart); Firefox Developer Edition, Nightly, ESR and LibreWolf keep it installed for good.
- **Chrome / Brave / Opera / Edge** only install a `.crx` from their store: the extension loads in "developer mode", once, and RDM updates it afterwards.
