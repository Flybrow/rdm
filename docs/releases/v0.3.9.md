Video streams fixed, less memory, and RDM tested for real on Linux.

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.3.9-x64-setup.msi`**, or let RDM install it by itself (the "Version 0.3.9 available" card) |
| Debian / Ubuntu | `rdm_0.3.9-1_amd64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.3.9-1.x86_64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`: extract, then `sh install.sh` |
| Chrome / Edge / Brave / Opera / Vivaldi… | from RDM (the "Browser extension" card), or `rdm-chromium.zip` |
| Firefox / Waterfox / LibreWolf / Floorp / Zen… | from RDM, or `rdm-firefox.xpi` (extension 0.4.6) |

## Fixed

- Some video streams (HLS) were refused with "separate MPEG-TS audio track is not supported" although their sound is inside the video: when a stream offers its own sound by default and another language on the side, RDM took the other one. They download now.
- On Linux inside Windows (WSL), RDM closed at start: WSLg's display server drops its window. RDM now uses the one that works there.

## Better

- Video streams take a third less memory while downloading (137–155 MB instead of 183–235 MB on a 600 MB 1080p stream), as fast as before.
- Internal: the update code is split into smaller files.

Checked on Windows 11 and on Ubuntu 26.04 (WSL): downloads identical to the byte, video streams merged and complete, the one-command installation and its removal, and the local bridge refusing the programs of another account.
