RDM now speaks **English** (and French), updates itself **silently**, and gains queues, proxies, checksums, site logins, clipboard capture and a native link with the browser extension.

![RDM](https://raw.githubusercontent.com/vincentxjoubert-lang/rdm/main/docs/screenshots/dashboard-dark.png)

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.3.0-x64-setup.msi`**: double-click, installed for your account, no administrator rights. From RDM 0.2.1: the "Version 0.3.0 available" card installs it |
| Ubuntu 26.04 | from the source code: `sh install-ubuntu.sh` |
| Debian / Ubuntu | `rdm_0.3.0-1_amd64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.3.0-1.x86_64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`: extract, then `sh install.sh --autostart` |
| Chrome / Brave / Opera / Edge | **from RDM** (the "Browser extension" card), or `rdm-chromium.zip` |
| Firefox / Waterfox | **from RDM**, or `rdm-firefox.xpi` |

The `.sig` files are the packages' signatures, which RDM checks before installing an update.

## What's new

- **English interface**, following the system's language; **Settings → Language** switches at once. The browser extension follows the browser's language.
- **Silent updates from RDM itself**, on Windows and Linux: one click (or none, with *Install automatically*: as soon as nothing is downloading) — no web page, no installer window. Every package is **signed** (Ed25519) and checked before it is installed; the signature binds the package to its version, so an old package cannot be passed off as a new one. On Windows RDM restarts by itself; on Linux the binary installed by `install.sh` is replaced in place, and `.deb` / `.rpm` packages are installed through the system's password prompt.
- **Native link with the browser extension** (native messaging): the browser starts RDM's connector itself, only for the RDM extension. Firefox, Waterfox and LibreWolf no longer need to be approved in RDM's window, and **a link sent from a page starts RDM** if it is not running. Sandboxed browsers (Flatpak, Snap) keep using the local bridge.
- **Named queues**, each with its own number of simultaneous downloads (right-click a download → *Move to*).
- **Speed limit per download** (right-click → *Limit the speed…*), applied at once, on top of the global one.
- **Change the link** of a download without losing what was downloaded (expired or moved link); the new link must serve the same file.
- **If the file already exists**: rename, overwrite or skip.
- **Checksums**: MD5, SHA-1, SHA-256 or SHA-512, checked as soon as the file is complete.
- **Proxies**: HTTP, HTTPS, SOCKS5 and SOCKS4a (names resolved by the proxy with `socks5h://`), the system's proxy, a *Test* button, and an **automatic mode**: direct first, a download that is blocked or very slow switches to the proxy by itself. Update checks and VirusTotal go through the same proxy.
- **Site logins** (HTTP Basic), sent only to their site and over HTTPS; passwords encrypted with DPAPI on Windows (private file on Linux). **Accept an invalid certificate** for one download only.
- **Clipboard**: a link to a captured format copied anywhere is offered in RDM (or downloaded right away, or ignored).

## Faster, on every connection

- More connections are added only while they make the download faster (the throughput is measured): a full line (slow ADSL, Wi-Fi at its limit) stops at the right number instead of piling up connections.
- One DNS lookup per server, shared by all connections (a slow resolver no longer delays each one); an address that stops answering (network change, VPN) is forgotten at once.
- Write buffers follow the connection's speed: large blocks for fast connections, little memory for slow ones.
- The window redraws less often when only numbers move (15 frames per second in front, 2 behind other windows), and RDM wakes up less when idle.

## Fixes

- A proxy `socks4://` with a user name made RDM crash.
- Talking to the running RDM (`rdm --quit`, a second launch) could go through the system's proxy.
- A setting this version does not understand (written by a newer RDM) reset *every* setting; a download list entry it cannot read emptied the whole list. Both now keep everything else.
- *Overwrite* could overwrite a file another download of the list was still writing.
- The first click after closing a dialog could be lost.
- Selectors of the settings could react to each other's clicks.
- The site's saved login was not used when asking the server for a file's name.

## Checks

Clippy without warnings and unit tests on Windows and Linux; extension checks (syntax, manifests, translations) and `web-ext lint`; end-to-end with real browsers (Chromium 154, Firefox 156): RDM started by the connector, downloads handed over, Firefox paired without approval, files identical to the source.
