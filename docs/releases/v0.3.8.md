Security and robustness, after a full review of the code.

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.3.8-x64-setup.msi`**, or let RDM install it by itself (the "Version 0.3.8 available" card) |
| Debian / Ubuntu | `rdm_0.3.8-1_amd64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.3.8-1.x86_64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`: extract, then `sh install.sh` |
| Chrome / Edge / Brave / Opera / Vivaldi… | from RDM (the "Browser extension" card), or `rdm-chromium.zip` |
| Firefox / Waterfox / LibreWolf / Floorp / Zen… | from RDM, or `rdm-firefox.xpi` (extension 0.4.6) |

## Security

- The local bridge (`127.0.0.1:9614`) closes at once a connection coming from a program of **another account** of the computer. Such a program could pose as the extension and hand RDM downloads; now it gets nothing.
- The **VirusTotal API key** is encrypted with your passwords (Windows' DPAPI) instead of being written in clear in `settings.json`. An existing key moves there by itself at the first start.
- Anti-SSRF: IPv6 addresses that carry a local IPv4 address (NAT64, 6to4) are recognised as local, like multicast and reserved addresses.
- Extension: cookies restricted to their site (`SameSite=Strict`) are no longer sent between two different sites under the same country domain (`a.co.uk` and `b.co.uk`).

## Better

- Less memory: each running download's task shrinks from 128 KB to under 3 KB, and installing the YouTube module no longer unpacks Deno (over 100 MB) in memory.
- A merged video (picture + sound) is safely on disk before it replaces its parts: a power cut right after can no longer leave an empty file.
- A damaged settings file is kept aside (`settings.json.bad`) instead of being replaced by the defaults for good.
- Internal: the download manager's core is split into smaller files; duplicated code is gone.
